# Выпуклые многоугольники на плоскости

Реализация класса выпуклых многоугольников с операциями пересечения, проверки нахождения точки внутри, триангуляции (веерный алгоритм), а также вычисления площади и периметра. При инициализации выполняется проверка выпуклости и нормализация порядка обхода вершин.

## Запуск
В директории **task-convex-polygons/** выполнить команду
```bash
python main.py
```

После запуска в консоли появится интерактивное меню:
```
--- Меню ---
1. Создать правильный n-угольник
2. Создать многоугольник из координат
3. Показать список
4. Пересечение
5. Триангуляция
0. Выход
```

Пункт **1** создаёт правильный n-угольник по количеству вершин и радиусу. Пункт **2** создаёт многоугольник из координат (например, `0 0 4 0 4 4 0 4`). Пункт **3** выводит список всех созданных многоугольников с площадью и периметром. Пункт **4** запрашивает индексы двух многоугольников и выводит их пересечение (площадь и периметр результата либо сообщение о пустом пересечении). Пункт **5** разбивает выбранный многоугольник на треугольники и выводит их координаты.

## Особенности реализации
Все геометрические вычисления устойчивы к ошибкам плавающей точки — используется константа `EPS = 1e-9` для сравнений. Класс `Point` неизменяемый (`frozen=True`), что гарантирует безопасность кэширования вычисляемых свойств. Свойства `area` и `perimeter` кэшируются через `cached_property`, поскольку многоугольники иммутабельны после создания. Алгоритмы триангуляции и пересечения вынесены в отдельные классы (`FanTriangulator`, `MyIntersector`), реализующие абстрактные интерфейсы `Triangulator` и `Intersector`, что соответствует принципу единственной ответственности и упрощает замену алгоритмов.

### Вопросы при зашите лабораторной

## Почему на строках 126 и 128 проверяется в одной < EPS, а в другой < -EPS?

< EPS - проверка для трех соседних вершин - отсекаются отрицательные значения (правый поворот) и значения около нуля (3 соседние вершины на одной прямой) 

< -EPS нестрогая проверка для фиксированного ребра и всех вершин в vertices, которая допускает значения около нуля. Лежать на одной прямой вершинам можно (ребро ab будет проверяться с вершинами a и b), так же это страхует от ошибок округления float: значение векторного произведения -1e-16 не должно считаться как правый поворот. 

Первая проверка не отличает выпуклый многоугольник и, например, звезду, т.к. не видит все вершины vertices, а только три соседние, поэтому добавлена вторая.

## Какое отношение принцип Барбары Лисков имеет к классу точки на плоскости?

Опирался на слайд 21/39 лекции 4: класс Point сделан неизменяемым, чтобы при появлении наследников (например, ColoredPoint) принцип подстановки Лисков не нарушался. 
Если абстрагироваться, незименяемость нужна, т.к. многоугольник хранит внутри себя Point, изменение координат вершины может привести к устареванию cached_property для area/perimeter и нарушению выпуклости.
